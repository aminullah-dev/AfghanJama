# شاخه‌ها — کدام زنده است و کدام نه

## ⛔ `claude/windows-parity` را **ادغام نکنید**

آخرین کامیتش `b34337f` است، **۴ اوت ۲۰۲۶**. از آن روز تا حالا `main`
جلو رفته و این شاخه سرِ جایش مانده.

اگر ادغامش کنید، `main` **۳۷٬۲۳۲ خط در ۲۰۰ فایل** از دست می‌دهد.

    git diff --stat origin/main origin/claude/windows-parity
    → 200 files changed, 1569 insertions(+), 37232 deletions(-)

**«۲۲۳ کامیتِ ادغام‌نشده» فریب‌دهنده است.** گیت‌هاب این عدد را نشان
می‌دهد و آدم فکر می‌کند ۲۲۳ کارِ نرفته آنجاست. این‌طور نیست: محتوای
آن کامیت‌ها در `main` هست، فقط شناسه‌هایشان فرق دارد چون تاریخچه یک
بار فشرده شد. عددِ کامیت را باور نکنید؛ `git diff --stat` را باور
کنید.

کاری که با آن باید کرد: **پاکش کنید.** چیزی از دست نمی‌رود.

    git push origin --delete claude/windows-parity

اگر پشیمان شدید، تا مدتی از همان شناسه برمی‌گردد:

    git push origin b34337f:refs/heads/claude/windows-parity

## چرا این فایل هست

کارفرما پرسید «انگار عقب می‌رویم، نکند شاخه‌ها کاری کرده‌اند؟» — و
پرسیدنش بجا بود. شش شاخه در مخزن نشسته بود که از بیرون هیچ‌کدام
نمی‌گفتند زنده‌اند یا مرده، و یکی‌شان ادغامش یک ماه کار را پاک می‌کرد.

اگر شاخهٔ تازه‌ای ساختید و کارش تمام شد، یا اینجا ثبتش کنید یا
پاکش کنید. شاخه‌ای که نه ثبت است نه پاک، روزی همین سؤال را دوباره
می‌سازد.
