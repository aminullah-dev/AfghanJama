# تحویل به نشستِ ویندوز

این فایل برای وقتی است که کار از یک نشستِ ابری (لینوکسی) به یک نشستِ
**روی خودِ ویندوز** منتقل می‌شود. نشستِ محلی تاریخچهٔ گفتگو را با خودش
نمی‌آورد؛ آنچه لازم است بداند اینجاست.

شاخهٔ کار: `claude/bug-check-fix-toovr0` — نسخهٔ `1.4.0 (8)`.

---

## چرا این انتقال لازم شد

نشستِ ابری در یک ظرفِ لینوکسی اجرا می‌شود و `dl.google.com` آنجا بسته
است، پس **Gradle اصلاً اجرا نمی‌شود**. تنها داورِ کامپایل، CI بوده.

سه چیز از این وضع بیرون ماند:

1. طرحِ Roomِ نسخهٔ ۶۲ ساخته نمی‌شود (پایین را ببینید — تنها قرمزِ CI).
2. `KhayatYar.exe` واقعاً باز نمی‌شود و کسی با ماوس در آن کار نمی‌کند.
3. کاغذ روی چاپگرِ واقعی چاپ نمی‌شود.

روی ویندوز هر سه ممکن‌اند.

---

## گامِ ۰ — چیزی که همین حالا CI را قرمز نگه داشته

`DB_VERSION` از ۶۱ به ۶۲ رفت (جدولِ `domain_events`). Room طرحِ هر
نسخه را **هنگام ساخت** می‌نویسد و آن فایل باید در گیت بماند، وگرنه
مهاجرتِ ۶۱→۶۲ آزمودنی نیست.

```
git pull
./gradlew clean
./gradlew :app:assembleDebug :desktop:compileKotlin
git add app/schemas desktop/schemas
git commit -m "طرحِ نسخهٔ ۶۲"
git push
```

باید این دو ساخته شده باشند:

- `app/schemas/com.afghanjama.data.AppDatabase/62.json`
- `desktop/schemas/com.afghanjama.desktop.data.DesktopDatabase/62.json`

**اگر ساخته نشدند، `build/` را پاک کنید و دوباره بسازید.** `DB_VERSION`
یک `const val` است و سرِ کامپایل درجا نشانده می‌شود؛ ساختِ افزایشی
گاهی KSP را دوباره اجرا نمی‌کند و طرح با عددِ قدیمی می‌ماند.

پس از این، CI باید کاملاً سبز شود (۴۴ بررسی).

---

## پیش‌نیازهای ساختِ محلی

مخزن این دو را ندارد و بی آن‌ها Gradle حتی `:desktop` را پیکربندی
نمی‌کند:

| چه | چرا |
|---|---|
| **JDK 17** | بندِ `jvmToolchain(17)`. JBRِ اندروید استودیو ۲۱ است و کافی نیست. |
| **`ANDROID_HOME`** | `local.properties` در مخزن نیست و AGP بی آن کار نمی‌کند. |

## اولین کاری که روی ویندوز باید انجام شود

اینها روی **بستهٔ واقعی** اجرا می‌شوند، نه روی classpathِ Gradle — و
این دو یکی نیستند؛ خرابیِ «دو Compose در یک بسته» فقط در بسته دیده
می‌شد.

```
./gradlew :desktop:duplicateClasses :desktop:screenSmoke
./gradlew :desktop:createDistributable
```

بعد `KhayatYar.exe` را از
`desktop/build/compose/binaries/main/app/KhayatYar/` باز کنید.

`screenSmoke` حالا از هر صفحه عکس هم می‌گیرد:
`desktop/build/screens/<بخش>.png` — ۳۴ فایل. آن‌ها را نگاه کنید؛
متنِ بریده و ستونِ خفه‌شده استثنا نمی‌دهند.

---

## آنچه هرگز آزموده نشده — و روی ویندوز باید بشود

سند `docs/WINDOWS.md` می‌گوید: «هنوز هیچ‌کس با ماوس در این صفحه‌ها کار
نکرده. رسم شدنِ فریمِ اول با ‹فرم پر می‌شود و ذخیره می‌کند› یکی نیست.»

به ترتیبِ اهمیت:

1. **یک فروش کامل ثبت شود** و عددِ صندوق پیش و پس از آن سنجیده شود.
2. **یک فاکتور روی چاپگرِ واقعی چاپ شود.** تا امروز هیچ کاغذی از این
   پی‌سی بیرون نیامده. راست‌به‌چپ و نشانهٔ افغانی (؋) دو جای مشکوک‌اند.
3. **دفترِ نسخهٔ ۶۲** باز شود — یعنی مهاجرت روی فایلِ واقعی، نه موقت.
4. **پشتیبانِ گوشی روی پی‌سی بازیابی شود** و برعکس.

## وضعیتِ فعلی

**صفحه‌ها:** ۳۳ از ۳۵ صفحهٔ `:core` روی ویندوز در دسترس‌اند. دو استثنا
در `tools/checks/deskscreens.py` با دلیل نوشته شده‌اند.

**آنچه فقط اندروید دارد و سدش واقعی است:**

| صفحه | سد |
|---|---|
| `AttendanceScreen` | اثرانگشت + `WorkManager` + ViewModelی که `Context` می‌گیرد |
| `CuttingScreen` | دوربین و مجوزِ اندروید |
| `OrderDetailScreen` | `OrderPhotoStrip` که هنوز در `:app` است |
| `SettingsScreen` | پشتیبان، اثرانگشت، انتخابگرِ فایل |
| `PinLockScreen`، `CrashReportScreen` | عمداً اندرویدی |

`OrderDetailScreen` تنها یکی است که ارزشِ ادامه دارد — سدش فقط نوارِ
عکس است و مرزِ `Photos` از قبل وجود دارد.

## قاعده‌هایی که نشستِ تازه باید بداند

- **اپِ اندروید تحویلِ کارفرما شده.** هر تغییری باید CI را سبز نگه
  دارد و اپِ تحویل‌شده را نشکند.
- **کلیدِ امضا هرگز به گیت‌هاب نمی‌رود** — نه در مخزن، نه در Secrets.
  کارفرما خودش در Android Studio خروجی می‌گیرد.
- **`Migrations.kt` دست‌نخوردنی است** — ۴۲ مهاجرتِ تاریخیِ اندروید.
  تغییرِ اسکیما فقط با یک `SchemaStep` در
  `core/.../SchemaMigrations.kt`، یک بار، برای هر دو سکو.
- **هر بررسیِ تازه باید روی کدِ عمداً خراب قرمز شود** پیش از آنکه
  باورش کنیم. بررسی‌ای که همیشه سبز است بدتر از نبودنش است
  (`tools/checks/README.md`).
- **ظاهرِ کاغذِ اندروید تصمیمِ کارفرماست.** یکی‌کردنِ سربرگِ اندروید و
  ویندوز فاکتوری را که کارگاه هر روز چاپ می‌کند عوض می‌کند. مرزِ
  `Docs.documentAction` عمداً روی **کار** بسته شد نه چیدمان، تا این
  تصمیم لازم نشود.
- **ماژولِ `:desktop` را جریانِ دیگری هم پیش می‌برد** (شاخهٔ
  `claude/windows-parity`، الان ادغام‌شده). پیش از تغییرِ بزرگ در آن،
  با کارفرما هماهنگ شود.

## بررسی‌ها

```
python tools/checks/run_all.py
```

۴۴ بررسیِ ساختاری، حدود دو دقیقه. تازه‌ترین‌هایشان در این شاخه اضافه
شدند: `contrast` (کنتراستِ WCAG روی ۶۲ جفت رنگ)، `spacing` (شبکهٔ
۴dp)، `rowweight` (ردیفی که بچهٔ وزن‌دارش خفه می‌شود)، `newtask`
(`startActivity` بی‌پرچم)، `eventtx` (رویدادِ بیرونِ تراکنش)،
`deskscreens` (صفحه‌ای که ویندوز راهی به آن ندارد).
