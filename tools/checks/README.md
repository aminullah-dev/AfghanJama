# بررسی‌های ساختاری

اینها پیش از Gradle اجرا می‌شوند و چیزهایی را می‌گیرند که کامپایلر هم
می‌گیرد — ولی در چند ثانیه، نه بعد از یک ساختِ ده‌دقیقه‌ای.

    python3 tools/checks/run_all.py

| بررسی | چه چیزی را می‌گیرد |
|---|---|
| `refcheck` | نمادِ خودِ پروژه که استفاده شده ولی ایمپورت نشده |
| `uicheck` | همان، برای نمادهای androidx/kotlinx |
| `balance` | پرانتز و آکولادِ نبسته |
| `paramcheck` | فهرستِ پارامترِ ناقص |
| `dupcheck` / `dupargcheck` | آرگومان یا پارامترِ تکراری |
| `fqcheck` | تابعِ الحاقیِ Flow که آزاد صدا زده شده |
| `extcheck` | تابعِ الحاقیِ پروژه بدونِ ایمپورت |
| `slotcheck` | آرگومانِ جاافتاده در پارامترِ تازه‌اضافه‌شده |
| `orphancheck` | صفحه یا مسیری که هیچ راهی به آن نیست |
| `dupnamecheck` | دو بررسیِ خودآزمایی با نامِ یکسان |
| `resetcheck` | جدولی که در «پاک کردنِ داده» دسته‌بندی نشده |

## دو قاعده

**۱. مسیرها از محلِ خودِ فایل پیدا می‌شوند، نه از پوشهٔ اجرا.**
شش تا از این اسکریپت‌ها با مسیرِ نسبی نوشته شده بودند و وقتی از پوشهٔ
دیگری اجرا می‌شدند صفر فایل می‌دیدند — یعنی بی‌سروصدا سبز می‌ماندند و
`refcheck` یک ایمپورتِ غایب را نگرفت. هر اسکریپتِ تازه باید ریشه را از
`__file__` پیدا کند.

**۲. هر بررسی باید ثابت کند چیزی می‌گیرد.**
بررسی‌ای که هرگز شکست نمی‌خورد فرقی با نبودنش ندارد. پیش از افزودن، یک
نسخهٔ عمداً خرابِ کد بسازید و مطمئن شوید گرفته می‌شود؛ بعد برش گردانید.
