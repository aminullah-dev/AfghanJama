# مدیریتِ وردپرس بدونِ مرورگر

## ⛔ پیش از `publish.py` این را بخوانید

**فایل‌های `docs/site/*.html` دیگر آینهٔ صفحه‌های زنده نیستند.**

صفحه‌ها بعد از انتشار مستقیم روی وردپرس ویرایش شده‌اند و از فایل‌های
مخزن جلو زده‌اند — امروز صفحهٔ زنده تقریباً **دو برابرِ** فایلِ مخزن
است (۱۵٫۴ در برابر ۸٫۳ کیلوبایت برای انگلیسی)، نسخهٔ مک دارد که در
فایل نیست، و یک صفحهٔ سوم به پشتو هست که اصلاً فایلِ محلی ندارد.

`publish.py` صفحه را **کامل بازنویسی می‌کند**. با فایل‌های فعلی
بزنیدش، آن اختلاف پاک می‌شود.

پس برای تغییرِ صفحه‌ای که زنده است، این ابزار را نزنید. فقط همان
رشته‌ای که عوض شده را جابه‌جا کنید:

```python
# محتوای خام را بگیرید ← رشته را عوض کنید ← برگردانید
GET  /wp-json/wp/v2/pages/<id>?context=edit&_fields=content
POST /wp-json/wp/v2/pages/<id>   {"content": "<متنِ تغییریافته>"}
```

شناسهٔ صفحه‌ها: انگلیسی `2060`، دری `2061`، پشتو `2062`.

> یک نکتهٔ عملی: وردپرسِ linumic.com به درخواستِ بی‌`User-Agent`
> جوابِ ۴۰۳ می‌دهد. یک `User-Agent: Mozilla/5.0` بگذارید.

`publish.py` جایش وقتی است که صفحهٔ **تازه‌ای** می‌سازید، یا صفحه‌ای
که هنوز دستی ویرایش نشده. آن وقت هم اول با `--status draft`.

---

> ابزار با سرورِ شبیه‌سازِ محلی کامل سنجیده شده — ساختن،
> به‌روزرسانی، و هر چهار حالتِ خطا — و REST APIِ خودِ linumic.com هم
> با همین روش کار کرده است.

---

## چرا این‌جا، نه مرورگر

سؤالِ اصلی این بود: «پروژه را محلی باز کنم تا سشنِ تازه وردپرس را
مدیریت کند؟» جوابش این است که **بازکردنِ پوشه به‌تنهایی هیچ قابلیتی
نمی‌دهد** — سشنِ محلی همان ابزارهایی را دارد که هر سشنِ Claude Code
دارد، مگر چیزِ تازه‌ای وصل شود.

ولی یک فرقِ واقعی هست: سشنِ محلی به اینترنتِ **واقعیِ** شما وصل است،
نه پشتِ پراکسیِ یک محیطِ ابری که `linumic.com` را می‌بندد. و مدیریتِ
وردپرس اصلاً نیازی به مرورگر ندارد — وردپرس یک REST API دارد که با
یک HTTP معمولی کار می‌کند. `curl` کافی است.

|  | مرورگر | REST API (این پوشه) |
|---|---|---|
| نیازمندیِ نصب | ابزارِ خودکارسازیِ مرورگر + نشستِ واقعیِ ورودِ شما | هیچ — پایتونِ استاندارد |
| شکنندگی | با هر تغییرِ ظاهرِ پیشخوان می‌شکند | با API که سال‌هاست پایدار است |
| چه می‌بیند | همان چیزی که شما در تب می‌بینید | فقط دادهٔ صفحه |

## گامِ ۱ — رمزِ برنامه بسازید (یک بار)

پیشخوانِ وردپرس → **Users** → **Profile** → پایینِ صفحه، بخشِ
**Application Passwords** → یک نام بدهید (مثلاً «Claude Code») →
**Add New Application Password**.

وردپرس یک رشتهٔ ۲۴ نویسه‌ای با فاصله نشان می‌دهد — این را **همان لحظه**
کپی کنید؛ دوباره نشانش نمی‌دهد.

> این رمزِ اصلیِ حسابتان **نیست**. قابلِ لغوشدن است (همان‌جا، با یک
> کلیک) و اگر لو برود، رمزِ اصلی دست‌نخورده می‌ماند — دقیقاً همان
> منطقِ کلیدِ امضای اندروید و ویندوز که در این پروژه رعایت شده.

## گامِ ۲ — اعتبارنامه را بگذارید

```
cp tools/wordpress/wp-credentials.example.json tools/wordpress/wp-credentials.json
```

و سه مقدار را پر کنید. این فایل در `.gitignore` است — با فایلِ واقعی
آزموده شد که پوشش می‌دهد.

یا به‌جایش متغیرِ محیطی بدهید:

```
export WP_URL="https://linumic.com"
export WP_USER="نامِ‌کاربری"
export WP_APP_PASSWORD="xxxx xxxx xxxx xxxx xxxx xxxx"
```

## گامِ ۳ — بفرستید

```
python3 tools/wordpress/publish.py \
    --slug tailor-erp \
    --title "خیاط‌یار" \
    --file docs/site/tailor-erp-fa.html \
    --status draft
```

اگر صفحه‌ای با همین نامک (slug) از قبل هست، **به‌روز** می‌شود. وگرنه
تازه ساخته می‌شود. هیچ صفحه‌ای پاک نمی‌شود.

خروجی لینکِ صفحه را می‌دهد. آن را باز کنید، ببینید، و اگر خوب بود:

```
python3 tools/wordpress/publish.py \
    --slug tailor-erp --title "خیاط‌یار" \
    --file docs/site/tailor-erp-fa.html --status publish
```

برای صفحهٔ انگلیسی همین را با `--slug tailor-erp-en` و
`docs/site/tailor-erp-en.html` تکرار کنید.

## چرا فایل‌های APK و MSI اینجا نمی‌آیند

این ابزار فقط **متنِ صفحه** را می‌فرستد، نه دو فایلِ سنگین. دلیلش در
`docs/site/گذاشتن-روی-سایت.md` نوشته شده: نصب‌کنندهٔ ویندوز ~۱۲۸
مگابایت است و وردپرس هم حجمش را نمی‌پذیرد هم پسوندش را. آن دو از راهِ
ریلیزِ گیت‌هاب می‌روند؛ لینک‌هایشان از قبل در متنِ HTML هست.

## اگر خطا داد

اسکریپت پیامِ **خودِ وردپرس** را نشان می‌دهد، نه فقط کدِ HTTP:

| پیام | یعنی چه |
|---|---|
| `وردپرس 401 برگرداند: …` | رمزِ برنامه یا نامِ‌کاربری غلط است |
| `وردپرس 403 برگرداند: …` | این کاربر اجازهٔ ساختن/ویرایشِ صفحه ندارد |
| `به … نرسیدیم: …` | نشانیِ `WP_URL` غلط است، یا سایت پایین است |
| `اعتبارنامه پیدا نشد` | نه متغیرِ محیطی هست نه `wp-credentials.json` |

هیچ‌کدام traceback خامِ پایتون نشان نمی‌دهند — همه پیامِ خواندنی
دارند، چون این آزموده شده (چهار حالتِ خطا با یک سرورِ آزمایشی).
